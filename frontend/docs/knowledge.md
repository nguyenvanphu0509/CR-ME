### DOM = Document Object Model.
Khi bạn viết HTML:trình duyệt sẽ đọc HTML này và tạo ra một cấu trúc object trong bộ nhớ đại diện cho trang web. Cấu trúc đó gọi là DOM.
Mỗi element HTML trở thành một DOM element/object mà JavaScript có thể truy cập và thao tác.
DOM là cầu nối giữa JavaScript và giao diện HTML.

Sign ! After getElementById('root') is the TypeScript non-null assertion: the programmer commits that this element definitely exists.
StrictMode supports detecting some unsafe side effects in development. Therefore some effects may be setup/cleanup more than once during development;
Side effect = the code changes or interacts with something outside itself. (The API request is also a side effect because you're interacting with an external system.) Because getting data from an API means interacting with something outside React's rendering calculation.
useState = "I need to store and change data in my component."
useEffect → performs side effects (Use it when you need to interact with something outside React's rendering process.)
useRef = A place for React to retain a value between renders, without changing that value without causing the component to re-render.
useRef can be used to hold a reference to a DOM object. useRef keeps the reference → so you can later get that exact DOM element and directly manipulate it. example like : đưa cursor vào input, giả lập click vào element, scroll màn hình tới element đó.
``` ts
useEffect(() => {
  ...
}, [])
```
The [] in useEffect is called the dependency array, towards this case, react nomarlly runs it at once when the component mounts.
Mount = The result of the initial render is inserted into the DOM.
Render = React calls the component to determine what the UI should look like.
A component can render many times, but in a specific lifecycle only mount once.
you must distinguish three type of [] in useEffect,
Multiple dependencies
``` ts
useEffect(() => {
  console.log("something changed")
}, [count, name])
```
Now the effect runs when either count or name changes.

## tsconfig.json
this file configues typescript
| Tùy chọn | Ý nghĩa trong project |
|---|---|
| `target: "ES2022"` | Mã JavaScript được hướng tới môi trường hỗ trợ cú pháp ES2022. Vite xử lý quá trình build thực tế, nên đây không phải toàn bộ cấu hình tương thích trình duyệt. |
| `lib: ["ES2022", "DOM", "DOM.Iterable"]` | Báo cho TypeScript biết có các API JavaScript hiện đại và API trình duyệt như `window`, `document`, `HTMLCanvasElement`. |
| `module: "ESNext"` | Dùng cú pháp module hiện đại như `import` và `export`. |
| `moduleResolution: "bundler"` | Tìm module theo cách phù hợp với bundler như Vite. |
| `jsx: "react-jsx"` | Cho phép viết JSX trong `.tsx` và dùng JSX runtime hiện đại của React. |
| `strict: true` | Bật kiểm tra kiểu nghiêm ngặt, giúp phát hiện sớm những trường hợp như truyền nhầm kiểu dữ liệu hoặc giá trị có thể là `null`. |
| `noEmit: true` | Chỉ kiểm tra mã; TypeScript không tự ghi file JavaScript ra đĩa. Script build chạy `tsc` kiểm tra trước, rồi Vite tạo sản phẩm build. |
| `paths` | Khai báo alias `@/*` tương ứng với `src/*`, ví dụ `@/components/Navbar`. Alias này cũng đã được cấu hình trong `vite.config.ts`. |
| `include: ["src"]` | Giới hạn các file TypeScript cần kiểm tra trong thư mục `src`. |

## postcss.config.js
PostCSS là công cụ chạy các bước xử lý trên CSS. Ở project này, Vite đưa CSS qua hai plugin:
1. Tailwind CSS đọc directive Tailwind và sinh CSS cho các class được dùng trong index.html và src/.
2. Autoprefixer bổ sung các tiền tố CSS cần thiết cho một số trình duyệt.

src/index.css + className trong TSX
  → PostCSS chạy Tailwind
  → CSS được sinh ra
  → Autoprefixer xử lý prefix
  → Vite đưa CSS đã xử lý vào bản build
